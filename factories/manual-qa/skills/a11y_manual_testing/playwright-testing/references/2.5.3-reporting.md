## Purpose

Transform stored, validated WCAG 2.5.3 results into the grouped bug data
required by the `accessibility-report` skill.

Apply this reference only after criterion evaluation and browser closure. Treat
grouping and bug preparation as reporting logic. Do not change the unchanged
evaluation algorithm in `2.5.3.md`.

## Input

Receive only stored evidence from the parent skill:

- exact `testedUrl`;
- execution mode;
- criterion execution status;
- validated summary counts;
- baseline results;
- dynamic state results and trigger context, when present;
- confirmed `FAIL` instances;
- processing validation outcomes.

Do not reopen or inspect the tested page.

## 1. Group confirmed failures

Group confirmed `FAIL` instances only after deterministic classification.

Group failures when they share:

- the same WCAG criterion;
- the same failure type;
- the same or equivalent root cause;
- the same or equivalent implementation pattern;
- the same remediation.

Prefer one bug with multiple affected elements. Do not group findings when
their cause or remediation differs.

Keep `missing_accessible_name` and `label_name_mismatch` as separate bugs
unless the stored evidence proves that their failure type, cause, and
remediation are the same.

Grouping must not add, remove, or reclassify a finding. Do not invent evidence
or report another WCAG criterion.

## 2. Prepare bug data

Prepare these fields for every grouped bug:

- Title
- WCAG
- Priority
- Steps to Reproduce
- Actual Result
- Expected Result
- Affected Elements
- Recommendations
- Techniques

Use:

- WCAG: `2.5.3 Label in Name (Level A)`
- Priority: `High`

### Missing accessible name

Use for failure type `missing_accessible_name`.

Title:

`[2.5.3][A] Form controls with visible labels are missing accessible names`

Actual Result:

`The affected form controls have visible text labels but do not have programmatically available accessible names. As a result, their accessible names do not contain their visible label text.`

Expected Result:

`The accessible name of each affected element should include its visible label text.`

Recommendations:

`Provide each affected control with an accessible name that contains its visible label text. Prefer programmatically associating the existing visible label with the control where appropriate.`

### Label and name mismatch

Use for failure type `label_name_mismatch`.

Title:

`[2.5.3][A] The accessible names of form controls do not match their visible labels`

Actual Result:

`The affected controls have computed accessible names that do not contain their corresponding visible label text.`

Expected Result:

`The accessible name of each affected element should include its visible label text.`

Recommendations:

`Update the accessible name so that it contains the visible label text in full. Include the visible label at the beginning of the accessible name where appropriate.`

## 3. Prepare reproduction steps

Use this precondition:

`Screen reader is turned on.`

For a baseline finding supply these ordered steps:

1. `Open <exact testedUrl>.`
2. `Navigate using the Tab key to one of the affected elements listed in Affected Elements.`
3. `Listen to the screen reader announcement.`
4. `Compare the announced accessible name with the visible label text.`

For a dynamic-state finding supply these ordered steps:

1. `Open <exact testedUrl>.`
2. Activate the supplied trigger using its stored visible label, accessible
   name, role, action, and locator.
3. `Navigate using the Tab key to one of the affected elements listed in Affected Elements.`
4. `Listen to the screen reader announcement.`
5. `Compare the announced accessible name with the visible label text.`

Replace the URL before hand-off. Do not leave any of these placeholders:

- `Open the tested URL`
- `Open tested URL`
- `Open <testedUrl>`
- `Open <tested URL>`
- `Open the page`

These are manual reproduction instructions. Do not imply that automated
testing used a screen reader. Do not claim that a specific screen reader
announced a value unless one was actually used.

## 4. Attach techniques

Attach both supplied techniques to every grouped bug:

- G208 — https://www.w3.org/WAI/WCAG22/Techniques/general/G208
- G211 — https://www.w3.org/WAI/WCAG22/Techniques/general/G211

Do not add techniques for another criterion.

## 5. Prepare affected elements

Include every grouped failure exactly once.

For each affected element supply:

- Visible Label
- Role
- Locator
- Accessible Name
- State

Use `State = baseline` for the initial rendered state. For a dynamic finding,
use its stored `stateId` and trigger context. Preserve `Empty` for an empty
accessible name.

Supply these evidence columns in this order:

```json
[
  {"key": "visibleLabel", "label": "Visible Label", "format": "text"},
  {"key": "role", "label": "Role", "format": "text"},
  {"key": "locator", "label": "Locator", "format": "code"},
  {"key": "accessibleName", "label": "Accessible Name", "format": "text"},
  {"key": "state", "label": "State", "format": "text"}
]
```

## 6. Validate reporting data

Verify:

- only confirmed `FAIL` instances produce bugs;
- every confirmed failure appears in exactly one grouped bug;
- bug count equals the number of grouped bugs;
- affected count equals the number of supplied affected elements;
- every bug uses the exact WCAG, priority, content, and techniques above;
- every first reproduction step contains the exact `testedUrl`;
- every dynamic-state bug includes its trigger step;
- no stored classification or evidence changed during preparation.

A no-issues result is eligible only when criterion execution is `COMPLETE`,
all required static and dynamic processing validations succeeded, and the
criterion `FAIL` count is zero.

When execution is `INCOMPLETE` or `BLOCKED`, retain the status and reason.
Do not prepare a complete no-issues conclusion.

## 7. Return reporting data

Return to the parent:

- grouped bugs;
- bug count;
- affected element counts;
- evidence columns;
- no-issues eligibility;
- reporting preparation status: `COMPLETE | INCOMPLETE | BLOCKED`;
- incomplete or block reason, when applicable.

Do not render HTML. Return control to the parent for automatic invocation of
`accessibility-report`.
